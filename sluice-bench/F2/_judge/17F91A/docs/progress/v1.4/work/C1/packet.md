## Approach
Everything is read-only over the engine; nothing under `src/` changes. Two new script files so the test can import the logic: `scripts/pacing-ledger.ts` (pure: builds the ledger object and renders markdown, no file IO) and `scripts/pacing.ts` (CLI: calls them, writes the two files). `package.json` gets `"pacing": "vite-node -c vitest.config.ts scripts/pacing.ts"` (same runner as `fixtures`). Scripts import by relative path (as `build-fixtures.ts` does).

**Pods** (a fixed list, each built with `sprintScopes(s).find(x => x.sprint.endsWith(...))` and `toHistory(s, mapping, scope)`, mapping = `config/state-mapping.json`, tz = the scenario's `tz`, not the machine's, for determinism): Halcyon `fixtures/scenarios/sprint-pods`, `Sprint 41`, pods Comet, Nova, Quasar, Pulsar (find in `h.scope.sector.pods` by `path`); Meridian `fixtures/scenarios/v1/meridian-sprint`, `Sprint 7`, the pod with the most scene events (count of `h.events` in range passing `sceneEvents(h, scene, SOLAR)`; ties by path; expect Convoy Planning Pod, say so in the record if not); plus Harbor Pod (`v1/pod-sprint`, `Sprint 13`, path ends `Harbor Pod`), added because PA-Q2 names it a yardstick. Scene = `` `pod:${areaKey}` `` on `SOLAR`, as `tests/unit/limelight.test.ts` does.

**Engine inputs through one door.** C4 will pass a device profile into the engine. So every engine call goes through two small functions in `pacing-ledger.ts` that take one `EngineInputs` object (`{ budgetMs?: number }` today, passed on to `buildScene`'s `budgetMs`; C4 adds `profile` there and nowhere else): `scheduleOf(h, scene, tz, inputs)` and `planOf(h, scene, beat, limelight, inputs)`. `buildLedger(inputs: EngineInputs = {})` threads it. The uncapped pass is the same call with `{ budgetMs: Infinity }` (the app's "All events" mode).

**The schedule** = `buildScene(h, h.range, tz, scene, SOLAR, undefined, inputs.budgetMs)` (what the app plays by default; budget 45 s). **Maneuvers per played beat** = `planManeuvers(h, beat, sceneFacts(paceFacts(h), podAreaKey), PACE_RULES, ENGAGEMENT.calm, { priorityOf, limelight: schedule.limelight })`, with `priorityOf = priorityFor(packFor(h), paceFacts)` omitted when undefined; exactly what `src/renderer/src/v1/plan.ts` does. `import '../src/shared/packs/all'`. Played beat = `durationMs > 0`.

**Wall-time frame (sums exactly to `schedule.totalMs`).** `orient` = `SOLAR.pacing?.(h, ref)?.orientMs ?? ORIENT_MS` (ref from `SOLAR.resolve(scene)?.ref`; 3000 for solar). Walking played beats in order, `gap_i = beat.presentationStartMs - prevEnd` (prevEnd starts at orient, then beat start + durationMs); it is a **day turn** if `beat.opensDay`, else a **gap**. `tail` = `totalMs - FINAL_HOLD_MS - lastEnd`; `final hold` = `FINAL_HOLD_MS`. Components: orient, gaps, day turns, tail gap, final hold, beats.

**Inside a beat (sums to `beat.durationMs`).** Segment [0, D] at every maneuver start, end, phase boundary, and span end. A maneuver is active from `afterMs` to `afterMs + durationMs`; its phase at offset o is the `phases` entry containing o, else `hold` (the crew's turn staying out after the last phase, P-7). In a segment with active maneuvers, the **lead** is the one with the latest end (ties: earliest start, then `protect` first, then id, then eventKey); the segment is **playing**, charged to the lead's row and phase. A segment with none active is **held open**: `note hold` if at or after the last planned end (a labelled turn's reading time, P-6), else `queue idle`. Row key = `id`, plus `/<variant>` and `/montage` when set (so `attachment.merge/first`, `objective.accomplish/beamed`, `.../arc` show apart).

**Waiting, as a second table (maneuver-ms: overlaps, so not wall time).** For each played maneuver with `afterMs > 0` and no `arc.merge` (an arc close is timed by design, not waiting): wait = `afterMs`. Find the binding predecessor: another maneuver in the beat whose `afterMs + durationMs` or `afterMs + max(durationMs, NOTE_MIN_MS)` equals this one's `afterMs` (take the one with the latest end; ties by key). Cause, inferred from the plan: **P-5** if they share an `agent`/`support` cast member; else **P-3** if either is `protect` and they share any cast key or `holds`; else **P-4** if the rule's `waitsFor` (cast `PACE_RULES` entries to `PaceRule`) names the predecessor's id and they share an eventKey; else **P-6** (the attention budget); no binding predecessor: **other**. **P-10 carry** is measured, not inferred: for beat j, `max(0, max end of an earlier beat's protect maneuver whose `keys` meet beat j's maneuvers' `keys`, in absolute ms, minus beat j's start)`. Expect 0 at 1× (a beat's duration covers its maneuvers); report the number.

**Output.** JSON: `{ pods: [...] }` with ms as integers, shares rounded to 3 places, rows sorted by wall ms descending then key; per pod `{ label, path, scenario, sprint, tz, events, beats: {total, played, silent, cutByBudget}, budgetMs, totalMs, uncappedMs, frame: {...ms, dayTurns}, playing: {byRule, byPhase, playingMs}, held: {queueIdleMs, noteHoldMs}, waits: {byCause, maneuvers, carryMs} }`. `cutByBudget` = played beats uncapped minus capped. No dates, no machine data, so two runs are byte-identical. Markdown: a header saying what it is and how to read it (1×, seconds to 0.1, waiting is maneuver-seconds), a summary table (one row per pod: total, uncapped, orient, gaps, day turns, playing, held, tail+hold), then per pod a `## <label> (<project>, <sprint>)` section with three tables: the time frame (component, s, %), rule by phase (s, with count and share), and waiting by cause. Write `docs/progress/v1.4/pacing-ledger.md` and `.json` (create dir if absent). Ignore unknown CLI args (C2 adds `--candidates`).

## Excerpts
Rules that apply (CLAUDE.md, project notes): no real ADO data, fixtures only; `src/shared/` stays pure and is not edited here; Node is `vite-node -c vitest.config.ts` for scripts; the busy fixtures (Pulsar, Quasar) must be in the ledger: "check the change on the busy fixtures it's for, not only on the default scene".

Layout, which the frame mirrors (`schedule.ts` `layout`): segments start `x = orient`; per played beat `x += g` (gap, or `turn` when `opensDay`), `presentationStartMs = x`, `x += durationMs`; then `x += gap(prev, end)`, then `x += FINAL_HOLD_MS`; `totalMs = x`. Constants: `FINAL_HOLD_MS` 1200, `DAY_TURN_MS` 1500, `BUDGET_MS` 45_000, `NOTE_MIN_MS` 1800 (maneuvers.ts:39), `OPENING_ORIENT_MS` 3000.

Planned shape (`contracts/maneuver.ts` 38): `{ id, eventKey, cast, phases: {phase, atMs, durMs}[], afterMs, durationMs, protect?: {keys, windowMs}, keys, variant?, holds?, arc?: {holders?, merge?}, quiet?, montage? }`; `afterMs` is from the beat's start.

Playbook rules named in the scope (05 §8.5): P-3 moments next (a protected moment waits for earlier moments sharing an actor or a held cast member); P-5 one person one thing (waits for any earlier maneuver flying the same agent or support); P-10 carry (a maneuver waits for an earlier beat's protected moment holding one of its actors, `runner.protectedFor`); P-6 attention budget (4 labels at once); P-7 a captain's turn (held until the ships leave).

Test pattern (`limelight.test.ts`): `toHistory(meridian, mapping, sprintScopes(meridian).find((x) => x.sprint.endsWith('Sprint 7'))!)`; `pod = (h.scope.sector as {pods: {areaKey; path}[]}).pods.find(...)`; `buildScene(h, h.range, TZ, `pod:${pod.areaKey}` as never, SOLAR)`; `mapping` from `tests/golden/helpers`.
