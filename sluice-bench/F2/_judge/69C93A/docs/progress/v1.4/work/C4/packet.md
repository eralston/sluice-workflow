## Approach (decisions made)
1. **Profile shape** (`src/shared/contracts/profile.ts`, zod `.strict()` at every level, `version: 1`): `id` (enum `desktop | laptop-battery | tablet | phone`), `title`, then
   - `pacing: { budgetMs, highlightBudgetMs }` (ints 5000..600000). Only the two budgets that are code constants today go in; HG-C's targets and E's `VOLLEY_WINDOW_MS` are added here later. The gap shape (`GAP_*`, `ORIENT_MS`, `DAY_TURN_MS`, `LEAD_MS`) stays in `constants.ts`: it is style, not a budget.
   - `render: { budget: { frameVsyncs, toleranceMs }, limits: { maxActiveFx }, switches: { paint, twinkle, ornament } }`. `switches` and `limits` are **the place C3 adds its cuts**: one key per cut, in the schema, in all four JSONs, in the 15 §11 table. `budget` is A3's frame budget (`perf.spec.ts`'s `2` and `VSYNC_TOLERANCE_MS`).
   - Left out on purpose: label caps (`ATTENTION_MAX`, `ROW_BUDGET`, `FEATURE_ROW_CAP`) feed the pure planner and projection, so they would move the goldens; and a holo-filter switch (B1's probe showed filters aren't Pulsar's cost). Both are listed under limitations, not silently dropped.
2. **Files.** `config/profiles/{desktop,laptop-battery,tablet,phone}.json` (beside `config/packs`; the scope's `profiles/` lives under `config/` to share the existing JSON import pattern, a relative import as `shared/packs/crm/index.ts` does). `src/shared/profile/bundled.ts` imports the four, `deviceProfileSchema.parse`s each at load, exports `BUNDLED` and `DESKTOP`. `src/shared/profile/resolve.ts` is pure (no fs).
3. **Values.** `desktop`: budget 45000, highlights 30000, vsyncs 2, tolerance 2, maxActiveFx 24, paint/twinkle/ornament on (today exactly). `laptop-battery`: same pacing, paint off, twinkle off, ornament on, maxActiveFx 24. `tablet`: budget 40000, highlights 27000, vsyncs 2, tolerance 3, maxActiveFx 16, paint on, twinkle on, ornament off. `phone`: budget 30000, highlights 20000, vsyncs 3, tolerance 3, maxActiveFx 12, paint off, twinkle off, ornament off. (Starting values; they are guesses until real devices, say so in 15 §11.)
4. **Resolving** (`resolveProfile({ overrideText: string | null, pinned?: string })` returns `{ profile, source: 'bundled'|'override'|'pinned', overridden, notice: string|null, reason: null|'parse'|'schema'|'merged'|'unknown-id' }`). Base is `pinned` if valid, else the override's `profile` key, else `desktop`. The override file `userData/profile.json` is `{ profile?, pacing?, render? }` with every nested key optional (`profileOverrideSchema`, strict, so a typo is an error); it is merged over the base and the merge is parsed by the full schema. Missing file: no notice. Unreadable JSON, a schema failure, a failed merge, or an unknown pinned id: use the bundled base alone (override ignored) with a one-line notice and a reason code.
5. **Reaching the renderer, synchronously.** Main (`src/main/profile.ts`: reads the file, honours `STAR_CHART_PROFILE` only when `!app.isPackaged`, writes `devlog.write('main', 'profile', { source })` and `'profile-fallback', { reason }`: codes only, never values) puts the state in `additionalArguments` as `--star-chart-profile=<encodeURIComponent(JSON)>`. Preload parses it with `profileStateSchema` and exposes `env.profile`; a bad or missing argument gives `DESKTOP` plus a notice. No IPC, no async boot, so the first schedule already has the right budget. Changing the override takes effect at the next launch (Settings says so).
6. **Renderer side** (`src/renderer/src/profile.ts`): `activeProfile()` (reads `window.starChart?.env.profile`, falls back to `DESKTOP` when there is no window: the gallery and unit tests), `patchProfile(partial)` (test hook only) and `onProfile(cb)`. Switch sites read `activeProfile()` at the moment of use, never at import, so a test can flip a cut off and on in one run (C3 needs this for its same-run before/after).
7. **Pacing wiring (C4b).** The pure engine never imports a profile for a choice: `ScheduleOptions.budgetMs` already exists. `buildBeatSchedule`'s fallback becomes `DESKTOP.pacing.budgetMs` (so the ~50 test calls without options keep the desktop numbers and the goldens do not move). `buildHighlights` gains a trailing `budgetMs?` (default `DESKTOP.pacing.highlightBudgetMs`). `playback.ts` `scheduleFor` passes `activeProfile().pacing` for all three paths; `allEvents` keeps `Infinity`. `scripts/pacing-ledger.ts`: `EngineInputs` gains `profile?: DeviceProfile`; the budget is `inputs.budgetMs ?? inputs.profile?.pacing.budgetMs`; `scripts/pacing-candidates.ts` line 329 `?? BUDGET_MS` becomes `?? (inputs.profile ?? DESKTOP).pacing.budgetMs`; `scripts/pacing.ts` gets `--profile <id>` (default none = unchanged output; the committed `pacing-ledger.md` must not change).
8. **Render wiring (C4c).** `ChartApp`: `painted` starts from `switches.paint`; an `applyProfile()` (subscribed with `onProfile`) re-applies paint (`setPaint`) and the twinkle layer (skip the per-frame alpha loop at ~line 1053 and hide the layer when off). `fx/timing.ts` `MAX_ACTIVE_FX` is deleted; `director.ts:235` and `movers.ts:63` use `activeProfile().render.limits.maxActiveFx`. Add in `timing.ts` one helper, `ornamentOk(v) = switches.ornament && v < CALM`, and use it where the code means "ornament allowed": `interpreter.ts` 148, 209, 805; `director.ts` 164, 408; `host.ts` 59. Leave the `volatility() >= CALM && waited < 4` waits (director 361, interpreter 365) alone: they are queueing, not ornament.
9. **Settings** (`settings/tabs/Theme.tsx`, a read-only fieldset "Device profile"): title, source, the notice if any, and "Override with profile.json in the app's data folder; applies at next launch". No new tab (`settings.spec` counts tabs).
10. **Docs, same change as the code.** 15 §10: retarget "Episode budget" to `@shared/profile/bundled.ts DESKTOP.pacing.budgetMs`, "Highlights budget" to `...highlightBudgetMs`, "Live effects cap" to `...render.limits.maxActiveFx`, "Frame budget" to `DESKTOP.render.budget.frameVsyncs, DESKTOP.render.budget.toleranceMs` (drop `unguarded`). New 15 §11 "Device profiles": table `profile-desktop` (Name, Value, Constant, Meaning; one row per profile key) and a deltas table for the other three (unchecked, listed in `UNGUARDED`). New `docTables.test.ts` check for `profile-desktop` (add the id to `GUARDED`): numbers via `numbersIn`, booleans as `on`/`off`. 03: `StarChartApi.env.profile`, the `STAR_CHART_PROFILE` row in the launch-variables table, `profile.json`. 14 §2.9: the contract. `tests/README.md`: a mapping row.

## Excerpts
- docTables rule (15 §1): "Change the constant and its row in the same change. `npm test` (`tests/unit/docTables.test.ts`) parses every marked table and fails until the two match." A Constant cell is `` `file.ts` NAME ``, shared files start `@shared/`, members are `NAME.member`; the `budgets` check accepts numbers and words only, so booleans need the new check.
- INV-15: "Only forward play animates; seeks snap." INV-12: replay and projection are pure. A budget is an input to the schedule, so the same profile gives the same schedule for play and seek.
- Project lens, frame budget: "dense scenes (Pulsar, 20 captains) sit near the p95 budget. Any per-object filter or extra pass needs a before-and-after perf run." (C4 adds none; it only moves where the numbers live.)
- Hard rules: `src/shared/` stays pure (no Electron/DOM/Pixi; the loader and fs live in `src/main`). Fixtures only; the override file in tests is a temp userData.
- Scope Decision (2026-10-31): "Perf is judged relatively... Absolute budgets come from the profile and are reported, soft."
- Today's settings contract: `userSettingsSchema.safeParse` on read; a corrupt file reads as defaults and writes `devlog.write('main', 'settings-corrupt', { reason })`. Copy that pattern.
