## Approach
Nothing under `src/` changes (B4 is editing it). Touches `scripts/`, one new unit test, and the ledger files. Two ways to estimate, both read-only over the engine:

**Method R (rule edit, exact reflow).** `planManeuvers`, `shapeOf` and `pacing(pack, {rules, facts, region})` all take a `rules` array, so a candidate that changes a rule is run as a real re-schedule: same call `buildScene` makes, with edited rules. Beat lengths, gaps, the 45 s budget fit and the cuts all re-run. Add `rules?: readonly ManeuverRule[]` to C1's `EngineInputs` (the one door; C4 adds `profile` beside it). `scheduleOf` with `inputs.rules` set calls `buildBeatSchedule(h, h.range, tz, { ...pacing(packFor(h), { rules, facts: paceFacts, ...(ref?.level === 'pod' ? { region: ref.key } : {}) }), include: sceneEvents(h, scene, SOLAR), hier: SOLAR, ...(budgetMs ? { budgetMs } : {}) })`; unset, it calls `buildScene` as now (C1's output must not change). `planOf` plans with `inputs.rules ?? PACE_RULES`. Check: the custom path given `PACE_RULES` gives the baseline `totalMs` exactly.

**Method P (post-hoc on the plan).** The sequencer is private, so E2, E4b, E4c are applied to a beat's plan: reuse C1's binding-predecessor inference (extract `bindingOf(m, beatMs) -> { pred, cause, anchor: 'end' | 'noteEnd' }` from `causeOf` in `pacing-ledger.ts`; `causeOf` calls it; ledger output unchanged). A maneuver with a binding predecessor may start `advance` ms earlier. Re-time each beat in `afterMs` order: `newStart = max(0, afterMs - (oldAnchor(pred) - newAnchor(pred)) - advance)`, anchor = pred's end (or `afterMs + max(durationMs, NOTE_MIN_MS)`); an arc close (`arc.merge`) follows its merge: anchor = merge `afterMs` + echo start + `ARC_IMPACT_MS`. A maneuver with no binding predecessor doesn't move. Beat gain = old max end - new max end; the pod's total falls by the sum of gains. No budget re-fit (stated; flag any estimate under `budgetMs` with "below the budget: gaps would re-expand"). Advances: **E2** P-6 waits: `tell + gather` of the waiting maneuver (it travels while waiting, claims labels at its act). **E4b** (P3) P-4 and P-6 waits only (P-3 and P-5 share an actor, which P3 forbids): `min(pred echo+disperse, own tell+gather)`. **E4c** (P4) P-5 waits: `pred end - (pred.afterMs + crewTimes(pred.phases).closeMs)`, floored at 0 (the captain waits near instead of leaving; `crewTimes` is exported). Where several apply to one wait, take the largest, not the sum.

**Method F (frame).** **E8** from the final schedule's played-beat gaps (`presentationStartMs - prevEnd`, as C1 computes), day turns and tail gap: a day turn becomes `max(floor, 0.6 x itself)`; gaps on the last day become `max(floor, 0.7 x itself)`; widening early days is ignored (optimistic). Two rows: floor `GAP_MIN_MS` (500, as scoped: expected 0 s, because every pod is over budget and already squeezed to 500 ms; say so in the table) and a sensitivity row, floor 250 ms.

**Candidates** (id, name, method, assumption). Constants named in `scripts/pacing-candidates.ts`, listed in the md's *Assumptions*:
- **E1** Fewer signals, R: `facility.enter` gather 1300 -> 715 (the summoner's flight, 55%, stays; the three beacon pulses and bearing go). Other cut effects cost no schedule time: this is a floor, E1's value is attention.
- **E2** Labels on arrival, P.
- **E3** Progress beam: 0 s alone (unused until E5); row kept, note "enabler".
- **E4a** (U1) Transform from gather, R: merge variant `first` becomes tell 300, gather 900, act 3500, land 500, echo 3000, disperse 900, `holds: ['facility']` (the 4.4 s transform starts at gather and the land waits for it: saves 2000 per first merge).
- **E4b** (P3), P. **E4c** (P4), P.
- **E4d** (P7) Short forms, R, a ceiling (the director picks which): every `protect` rule, and its variants, has each phase x `MONTAGE_PACE` (0.6, the engine's existing quick-pace constant), except a close's `land`, which stays `CLOSE_SLIDE_MS`. The captain's plate minimums still floor it.
- **E5** The director, R: from the baseline plans, the set of merges to replace = `attachment.merge` maneuvers with no `arc.merge` close in their beat, minus each author's first merge (hero shot; author = `cast.agent[0]`) and minus each day's climax (day = count of `opensDay` beats; climax = the protected maneuver with most `keys`, ties: has an arc partner, then earliest) when that is a merge. Edited rules: the merge gets `when` excluding that set; a new rule `attachment.beam` (id string, narrative, not protected, `match` as the merge's, `when` = in the set, `cast` = `castOf({ agent: [author ?? e.changedBy], target: workOf(f, mv.key, e.occurredAt) })`, phases tell 200, act 900, echo 400 = 1.5 s, no gather so no held turn). Trade-down and the target are not modelled here: **E5 + E4d** is its ceiling.
- **E6** Multi-fire volleys, R, coarse: merges are grouped per facility (`cast.facility[0]`) in absolute order (`beat.presentationStartMs + afterMs`); a group starts at its first merge; later merges within `VOLLEY_WINDOW_MS` = 10_000 of it and on the same day (no `opensDay` between) are members. A member's variant is tell-less `phases(['echo', 1500])` (its split beam only; its arc close still lands at echo start + 1300; no gather, so no formation or held turn). Not modelled: the union formation's labels.
- **E7** Sector sweep, R, a lower bound (within-beat only): in a beat with n >= 2 creations (`piece.appear` / `threat.emerge`), the first plays as a sweep (tell 300, act 900 + 250 x (n-1), echo 400) and the others are excluded by `when`.
- **E8**, **E8 (floor 250 ms)**: F. **E9** Camera: 0 s (renderer-only, no schedule time); row kept.
- **Stack** = E1, E2, E4a, E4b, E4c, E5, E6, E7, E8 together (rule edits composed in that order, wrappers chaining `when` with `&&` and variants first-hit; sets taken from the baseline plans; then P on the edited plans; then F). **Stack + short forms** = Stack + E4d. Not unranked sums: interactions are real.

**Output.** `buildCandidates(inputs = {}, only?: string[]) -> { pods: { label, baselineMs, rows: CandidateRow[] }[] }`, `CandidateRow = { id, name, method, assumption, savingMs, savingPct (1 dp), estTotalMs, touched, detail, flag? }`; `touched` counts what changed (merges replaced, maneuvers advanced, ...) so a 0 s row says whether it fired. `renderCandidates(c): string` returns a `## Candidates` section: intro (modelled, not built; positive = shorter; the method letters), *Assumptions* list, a matrix (rows = candidates in id order; columns Comet first, then the other five pods; cells `12.3 s (18.3%)`), then per pod `### <label>`: a table ranked by saving (rank, item, saving s, %, est. total s, assumption + detail), the two stack rows below the ranking. `pacing.ts`: `--candidates` appends `renderCandidates` after the ledger markdown and writes `pacing-candidates.json`; without the flag it behaves as C1 (md without the section). Use `###` under `## Candidates` so C1's test (which finds `## <label> (`) still holds. Regenerate the committed files last with `npm run pacing -- --candidates`.

## Excerpts
Scope: "For each E item, the ledger adds a modelled saving per pod: the same report with the candidate's rule applied to the numbers (a phase overlapped, a maneuver replaced by a progress beam, a group merged), without building it. Each estimate states its assumptions. The output is a *Candidates* section in `pacing-ledger.md`, with a ranked table per pod, for HG-C to read." Risk none; touches `scripts/pacing.ts`, the ledger.

Why waits happen (`sequence`, maneuvers.ts): a protected moment starts after earlier moments it shares an actor or held cast with (P-3); "One person does one thing at a time (22 A11, R8): any maneuver starts once every one placed before it that flies the same person has finished" (P-5; a flying crew is held to `crewTimes(...).leaveMs`); a rule starts after rules it `waitsFor` in the same event (P-4); "a labelled interaction starts once its labels fit under `ATTENTION_MAX`" (4; P-6). The arc close starts at `merge.startMs + phaseStart(merge.phases,'echo') + ARC_IMPACT_MS` (1300). A beat's length is the max of `startMs + heldMs` (`heldMs` = `max(durMs, NOTE_MIN_MS)` when labelled).

Budget (schedule.ts fit): over budget, gaps squeeze to `GAP_MIN_MS` (500), then accents are cut lowest-priority first, never High or essential beats. C1's ledger: every pod is over 45 s with all gaps and day turns at 500 ms.

Project rules: fixtures only; `src/shared/` is not edited; heed the busy fixtures (Pulsar, Quasar are in the table); E1-E9 are not built, nothing in `docs/15` moves.
